# UI の文字と文言を読み取れる 8 規則

書かれたものを読めて、意味が取れるかを点検する。
利用者が画面に書かれたものを読む場面で、読む順番、意味のまとまり、数値の比較、操作の行き先、予定の時点が伝わるかを確認し、足りなければ補うためのスキルである。

## このスキルが守るもの

守るのは規則とその目的であり、特定の見た目ではない。
規則の説明に出る文言や表示方法は理解を助けるための例であり、書体名、ポイント数、色コード、固定した改行位置を揃える必要はない。
書体の組み合わせや字間の演出は品格や表情をつくるためのものであり、このスキルでは扱わない。
読む順番は文章要素の役割が伝わるかを扱い、画面全体のまとまりや情報の優先順位は扱わない。

適用の可否は、対象アプリの性質（利用者、利用頻度、業務上の重要度、既存の文章規約、技術的制約）を踏まえて判断する。
規則を機械的に当てはめると、短い文に不要な改行を入れたり、比較しない数値に整列を強いたりして、かえって読み取りにくくなる。
各規則の「対象外」と「別の表現で満たす条件」を確認してから提案する。

## 進め方

1. **対象の把握**：どの画面、コンポーネント、フローの文字と文言を扱うかを特定する。
   アプリ全体の性質（業務システムか、一般消費者向けか、開発者向けか）と、既存のデザインシステム、文章規約、用語集を確認する。
   画面構成は、画面のルーティングとコンポーネントの一覧から把握し、どの文字列がどの操作や判断に関係するかを整理する。
2. **文字と文言の洗い出し**：見出し、本文、ラベル、補足、操作文、数値、日付、時刻を列挙する。
   文字列ごとに、読み手が何を理解し、どの作業へ進む必要があるかを確認する。
   読み込み中、空、失敗、権限不足、削除、完了、入力不備など状態の有無や遷移は ux-state-review で扱う。
3. **規則ごとの判定**：該当する文字と文言について、[references/rules.md](references/rules.md) のチェック観点で現状を確認する。
   判定は「満たす」「満たさない」「適用しない（理由）」「情報不足（確認事項）」の四つに分ける。
   「適用しない」にできるのは、その問題が起きないか、起きても利用者が困らない場合に限る。
   チェック観点どおりの表示ができなくても別の手段で目的を達成できる場合は、rules.md の「別の表現で満たす条件」に従い、その手段の有無で「満たす」「満たさない」を決める。
   文言や画面だけでは分からない対象、利用者の読み方、表示条件は、推測で判定せず「情報不足」として確認事項を添える。
4. **適用**：「満たさない」ものについて、そのアプリの文章規約とデザインシステムに沿った直し方を提案するか、依頼されていれば実装する。
   直し方は規則の目的から導く。
   規則の説明にある表示方法をそのまま持ち込まず、対象アプリの語彙と利用者の作業に合わせる。
5. **報告**：後述の形式で結果をまとめる。

レビューだけを依頼された場合は 4 を提案にとどめる。
実装を依頼された場合も、規則の適用可否に判断が分かれる箇所は提案として残し、確実な箇所だけを実装する。

## 8 つの規則

各規則の詳細なチェック観点、対象外の条件、別の表現で満たす条件、実装上の注意は [references/rules.md](references/rules.md) にある。
判定するときは必ず参照する。

| 番号 | 規則 | 目的 | 対象となる文字と文言 |
|---|---|---|---|
| 01 | 読む順番をつくる | 見出し、本文、補足の役割が分かり、読む順番を迷わない | 異なる役割の文字が同居する画面 |
| 02 | 強調を一語に絞り意味のまとまりで改行する | 強調点と文の切れ目が分かり、一文を追いやすい | 強調を含む文、見出し、短い説明 |
| 03 | 数値の桁と単位をそろえる | 数値の大小と条件を同じ基準で比べられる | 金額、件数、割合、測定値 |
| 04 | 識別子を意味のある塊で示す | 長い番号を読み違えず、転記や照合をしやすくする | 予約番号、ID、コード |
| 05 | 行間と段落間で読み進める単位を示す | 文と段落の境界が分かり、読み飛ばしや戻りを減らす | 長文、説明文、箇条書き |
| 06 | 文字と背景の明暗差を確保する | 文字が背景に埋もれず、内容を読み取れる | 本文、ラベル、補足文 |
| 07 | リンクとボタンに行き先と結果を書く | 操作の行き先や押した結果を予想できる | リンク、ボタン、行内操作 |
| 08 | 日付と時刻を具体化する | 予定や期限がいつかを一度で把握できる | 予定、期限、予約、履歴 |

## 適用判断の原則

規則を当てはめるかどうかは、次の順で考える。

- **その問題が実際に起きるか**：比較する文字の役割がない画面に階層を足す必要はない。
  利用者が読んだり転記したりしない内部識別子は、規則 04 の対象にしない。
- **利用者がその問題で困るか**：困らなければ規則の目的が成立しない。
  長い説明文では行間や段落間の差が効くが、一行で完結する短い通知に同じ調整を求める必要はない。
- **既存の規約と衝突しないか**：アプリにデザインシステムや共通の文章規約があるなら、その語彙で目的を実現する。
  規則の目的を満たす別の表現が既にあるなら、それを「満たす」と判定してよい。
- **コストに見合うか**：表示内容の変更にデータ定義、翻訳、タイムゾーン、バックエンドの変更が必要な場合がある。
  その場合は、画面だけで実現できる部分と追加開発が必要な部分を分けて提案する。

判断に迷ったときは、規則の目的（表の「目的」列）に立ち返る。
目的が満たされていれば手段は問わない。

## ux-state-review との境界

このスキルは、通常時の文字と文言から役割、意味のまとまり、比較、行き先を読み取れるかを扱う。
読み込み中、空、失敗、権限不足、削除、完了、入力不備の状態があるか、その状態で何を表示しどう遷移するかは ux-state-review で扱う。
状態に現れる文言を確認するときも、状態の設計と混ぜず、文字の階層や具体性だけをこのスキルの判定に残す。

## 報告の形式

レビュー結果は次の形式でまとめる。
対象が多い場合は画面ごとに繰り返す。

```markdown
## 対象
（画面やコンポーネントの名前と、アプリ全体の性質の要約）

## 判定
| 規則 | 判定 | 現状 | 提案 |
|---|---|---|---|
| 規則 01 読む順番 | 満たさない | 見出しと本文が同じ階層で表示される | 役割を区別できる既存の表現を適用 |
| 規則 02 強調と改行 | 満たす | 強調点と文の切れ目が読み取れる | なし |
| 規則 03 数値と単位 | 適用しない | 比較する数値がなく、単位や条件の理解も要らない | なし |
| 規則 07 リンクとボタン | 情報不足 | 操作後の行き先を画面だけでは確定できない | 遷移先と操作結果を確認してから再判定 |
| ... | | | |

## 優先して直す項目
（利用者への影響が大きい順に、理由を添えて）

## 判断を委ねる項目
（適用の可否がアプリの方針に依存するもの。選択肢と推奨を添えて）
```

「判断を委ねる項目」には、規則の適用によって開発者が決めるべきこと（識別子を表示上だけ区切るか、日時にタイムゾーンを添えるか、既存のリンク文言をどこまで具体化するか、など）を残す。
自走中はメインセッションの判断で推奨案を採り、決めるべき内容は一覧にして開発者に提示する。

## 実装時の注意

- 文言は、そのアプリの既存の文言のトーン（敬体か常体か、専門用語の使い方）と用語集に合わせる。
- 見出しやラベルの役割は、見た目だけでなく意味構造にも反映する。
  デザインシステムのタイポグラフィ定義が階層を担う場合は、個別の画面で書体名やサイズを指定せず、その定義を使う。
- 強調は一文の意味を変える語や短い語句に絞り、色だけに頼らない。
  改行は語句や文節の関係を切らず、表示幅や文字拡大で変わっても読み順を保つ。
- 数値は比較する単位を揃え、右揃えなどの整列は目的に応じた手段として使う。
  単位や請求条件は、どの数値に対応するかを視線と支援技術の両方で追える位置に置く。
- 識別子の正式な値は変更せず、表示上の区切りとコピーする値を分ける。
  区切りはドメイン上意味のある塊に限り、任意の文字数で一律に分割しない。
- 行間と段落間は、本文の行を追う間隔と話題が変わる間隔を区別する。
  長い読み物は左揃えを基本とし、短いメッセージの中央揃えを一律に否定しない。
  箇条書きの折り返しは、記号ではなく本文の始点に揃える。
- 文字と背景の明暗差は、実際の表示色と背景の組み合わせで確認する。
  コントラスト比の目安は rules.md の規則 06 に従う。
  テーマ、ホバー、フォーカス、文字拡大後でも本文や補足文が背景に埋もれないかを確認する。
- リンクとボタンの文言は、見えている周辺文脈と支援技術に伝わる名前を合わせ、行き先や押した結果を表す。
  状態が変わった後の案内、再試行、削除確認、完了後の流れは ux-state-review の規則と分けて扱う。
- 予定や期限の日付には、必要に応じて曜日、時刻、タイムゾーンを添え、表示地域の書式に合わせる。
  相対的な日付だけで判断させず、後から見返しても時点を特定できる情報を残す。
- 変更後は、短い文、長い文、長い数値、異なる単位、長い識別子、日付の境界を実際に表示して確認する。
  文字拡大、狭い表示幅、長い翻訳、テーマ変更で意味のまとまりや行き先が失われないかを確認する。
  再現方法がない表示条件は、確認できていないと報告に書く。
